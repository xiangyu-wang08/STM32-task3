# 通信科协 STM32 软件任务三 · PWM 生成、测量与波形采集

这次我让 STM32F103C8T6 自己产生 PWM，再把输出接回定时器输入和 ADC。我先实现串口调参和两种测频方法，再分开做 100 Hz 的实时采集和 50 kHz 的 DMA 单帧采集。OLED 用来读频率和占空比，VOFA+ 用来观察波形。

## 任务书要求与实现

| 要求 | 我的实现 |
| --- | --- |
| 用定时器产生 100 Hz～100 kHz 的 PWM，串口可调频率和 10%～90% 的占空比，要求占空比按 10 个百分点调节 | TIM3_CH1 在 PA6 输出 PWM，`f50000` 设置频率，`50%` 设置占空比。10%、20% 到 90% 各档都可设置，当前代码还接受区间内的其他整数百分比。 |
| 由另一个定时器测周期和占空比，在 OLED 上实时显示 | TIM2 在 PA0 用 PWM 输入模式捕获周期和高电平时长，OLED 显示频率和占空比。 |
| 用 ETR 测频，在 OLED 上显示，由按键切换输入捕获与 ETR | 复用 TIM2 的 PA0/ETR 输入，TIM4 提供 100 ms 测量窗。PB11 在两种测量方式间切换。ETR 模式显示频率，占空比位置显示 `--%`。 |
| 采集 100 Hz 波形，通过串口实时流式发送到 VOFA+ | ADC1 读取 PA1。TIM1 每 1 ms 从 ADC 取一个结果并写入队列，主循环从队列读取并发送。 |
| 切换高速采样，用 ADC 和 DMA 缓存一帧，再经串口发送给 VOFA+，基本还原 50 kHz PWM | 每次收到 `h` 暂停 TIM1 取样，用 DMA1 通道 1 采 256 点，采满后发送一次。收到 `l` 恢复低频实时采样。 |

任务书要求任务报告和演示视频。报告还要对比测周法与 ETR 在不同频率下的表现，解释 ADC 采样率、缓存点数和串口速率如何限制高频边采边传。高频输出若受定时器计数限制，取最接近设定值的硬件输出。

## 开发和排查过程

### 1. 先让串口指令真正改变 PWM

最初发串口指令改不了频率。任务记录里查到的一处原因是忘了在主程序调用 `Serial_Init()`。补上初始化后，我用串口助手确认接收路径，再在 VOFA+ 里发文本。`f100` 里的 `f` 是命令字符，`atoi(Serial_RxPacket + 1)` 从下一个字符读取频率。串口接收要求包头有一个空格，行尾是 CRLF，调试时也要核对这两部分。后来我还碰到过 Keil 烧录变慢、发命令时断点始终不进的情况。重启电脑后烧录恢复，另一次重插 ST-Link 并复位后也恢复了接收。原因没有单独定位，所以我把它记作调试现场的现象。遇到收不到命令时，先用串口助手和已知格式确认能接收，再判断是命令解析问题还是烧录、复位或连接状态的问题。

调频时我还遇到过没有改占空比命令、占空比读数却跟着变的情况。PWM 的周期是 `ARR + 1` 个计数，高电平时长由 CCR1 决定。只改周期会改变两者的比值，所以我保存目标占空比。现在 TIM3 的计数时钟是 6 MHz，按目标频率四舍五入计算周期计数，再用新的周期计数和目标占空比重算 CCR1。这样调频后会维持原设定的占空比，输出还会受到整数计数的量化限制。 [PWM.c](Hardware/PWM.c)

### 2. 区分 PWM 输入的高频量化误差与 ETR 的计数误差

我用 TIM2 的 PWM 输入配置捕获上升沿间隔和高电平时宽。当 TIM2 计数时钟为 1 MHz，50 kHz 的 PWM 一周期约有 20 个计数，100 kHz 只剩约 10 个。周期读数只变化一个计数，换算出的频率就会跳一大档。我在高频调试时看到过约 83.3 kHz 和 100 kHz 之间的跳变。在 1 MHz 计数时钟下，用 12 和 10 作为换算分母，正好会得到这两档读数。高电平时长也按计数格量化，频率越高，小占空比越容易受这个限制。输出端 TIM3 的整数周期和输入端 TIM2 的测量误差需要分别看。当前 `IC_GetFreq()` 用 `CCR1 + 1`，`IC_GetDuty()` 用 `CCR1`，验收比较高频读数时需考虑这个额外计数。刚切回输入捕获时，`CCR1` 还可能为零，当前占空比计算尚未做零值保护。 [IC.c](Hardware/IC.c)

ETR 模式换成让外部边沿驱动 TIM2 计数。TIM4 每 100 ms 读一次，两次计数之差乘 10 就是 Hz。16 位计数器从 65535 回到 0 时，差值按 65536 补偿。以 100 kHz 为例，一窗约数到 10000 个边沿。一窗相差一个边沿对应 10 Hz，适合和测周法对比。低频时一窗的边沿数少，测周法通常更容易获得细分读数。按键切换时复位并重新配置 TIM2，离开 ETR 时也停止 TIM4。 [ETR.c](Hardware/ETR.c) · [Timer.c](System/Timer.c) · [main.c](User/main.c)

### 3. OLED 开启时，为什么 VOFA+ 画出了尖波

最初的低频采集用单个变量保存 ADC 值，主循环再发串口。任务记录里做过一次对照：临时禁用 OLED 显示后，波形比禁用前规整。结合程序结构，OLED 刷新占用主循环时间，期间新采样会覆盖还没来得及发送的旧值。VOFA+ 把剩余点按固定间隔画出来，高、低电平平台就可能变得很短。

我把单变量改为 128 个元素的环形队列。TIM1 中断按写下标依次存点，主循环按读下标依次取点。队列满时跳过新样本，避免覆盖未发送的数据。TIM1 和 TIM4 各有自己的中断优先级，但 NVIC 的分组是全局设置，串口和两个定时器的初始化统一使用 Group 2。普通模式只保存每 1 ms 读取到的结果，ADC 本身持续转换。 [main.c](User/main.c) · [Timer.c](System/Timer.c)

### 4. 高频时先采一帧，再慢慢发送

连续转换的 ADC1 按 12 MHz ADC 时钟、1.5 个采样周期和 12.5 个转换周期计算，理论上约每 1.17 µs 转换一次。50 kHz 的 PWM 一周期为 20 µs，约能留下 17 个采样点。115200 波特的串口即便按 8N1 连续传输，理论上也只有 11520 字节每秒，一个十进制采样值还常占多个字符，所以我把采集速度和发送速度分开。

收到 `h` 后先停 TIM1 的低频读取。DMA 以普通模式从 ADC 数据寄存器搬到 `AD_DMAValue[]`，搬满 256 点后，再逐点发给 VOFA+。我在启动下一帧之前显式清除上一次的 `TC1` 完成标志，避免读到旧标志而提前结束等待。停用 DMA 通道只改变使能位，所以清标志单独做。写发送循环时，Keil 提示 `uint8_t n = 256` 会变成 `0`，我把点数和循环下标都改成 `uint16_t`。这样下标在发送完第 256 个点后能递增到 256 并正常退出。 [AD.c](Hardware/AD.c) · [main.c](User/main.c)

连续多次发送 `h` 时，我在 VOFA+ 上偶尔看到一段高电平平台明显变长。截图里该平台跨过距最新数据约 256 个点的位置，与帧长吻合。这个现象很可能来自相邻两帧在不同 PWM 相位结束和开始，VOFA+ 把它们画成了连续曲线。复现时清空波形缓存，再单独触发一帧，观察帧内几个完整周期。界面默认的 `1 ms/点` 会拉长这帧的显示时间，按采样配置估算的实际间隔约为 `0.00117 ms/点`。

## 接线与复现

在 Keil µVision 打开 [project.uvprojx](project.uvprojx)，编译并下载。将 PA6 的 PWM 输出同时接到 PA0（输入捕获或 ETR）和 PA1（ADC）。OLED 使用 PB8/SCL、PB9/SDA，PB11 接模式切换键。USART1 的 PA9/TX 接串口模块 RX，PA10/RX 接模块 TX，模块与开发板共地，串口参数为 **115200、8N1**。

VOFA+ 按每行一个十进制 ADC 值接收。发送命令时在正文前保留 **一个空格**，末尾使用 CRLF。表中的引号只用于显示开头的空格。

| 发送正文 | 作用 |
| --- | --- |
| `" f100"` | 设置 PWM 为 100 Hz |
| `" f50000"` | 设置 PWM 为 50 kHz |
| `" 50%"` | 设置占空比为 50% |
| `" h"` | 采集并发送一帧 256 点高速数据 |
| `" l"` | 恢复约 1 kHz 取点的实时数据流 |

1. 在 **100 Hz、50%** 下观察 VOFA+ 的实时波形。按 PB11 在两种测量方式间切换，分别记录 OLED 频率和输入捕获的占空比。
2. 在 **50 kHz、50%** 下用 `h` 采帧，等发送完成后清空 VOFA+ 缓存，再用 `h` 单独采一次。观察帧内的高、低电平和重复周期。
3. 再改回 **100 Hz** 并发 `l`，确认 VOFA+ 恢复持续刷新。比较测频方法时可分别记录低、中、高频的设定值和 OLED 读数。
